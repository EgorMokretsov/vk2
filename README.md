# VK2 — погода по городам

Решение задания на Python: загрузка городов из файлов, получение текущей погоды
через wttr.in, вывод данных каждого города и статистики по странам.
Используется только стандартная библиотека Python. Устанавливать пакеты через
pip или получать API-ключ не нужно.

## Запуск

Нужны Python **3.10 или новее** и доступ к интернету.

```bash
git clone https://github.com/EgorMokretsov/vk2.git
cd vk2
python weather.py
```

В Windows при необходимости используйте `py weather.py`, в Linux/macOS —
`python3 weather.py`.

По умолчанию программа читает **оба исходных файла** из папки
`файлы со списком городов`. Пути по умолчанию определяются относительно скрипта,
поэтому запуск возможен из любой рабочей папки. Оба файла содержат одинаковые
восемь городов. Повторы удаляются до выполнения HTTP-запросов.

Можно указать один или несколько других файлов:

```bash
python weather.py "файлы со списком городов/Cities.txt"
python weather.py cities1.txt cities2.txt --timeout 30 --retries 1
python weather.py --help
```

Формат входа: UTF-8 (в том числе с BOM), один город на строку. Пробелы по краям
и пустые строки игнорируются. Повторы сравниваются без учёта регистра,
сохраняются написание и порядок первого появления. Пути, заданные пользователем,
отсчитываются от текущей рабочей папки.

## Выполнение требований

1. `load_cities()` загружает список уникальных городов в память.
2. `fetch_weather()` для каждого города запрашивает
   `https://wttr.in/{City}?format=j1`, кодируя название для URL. Формат JSON
   описан в [официальной документации wttr.in](https://github.com/chubin/wttr.in#json-output).
3. Модель `WeatherData` содержит `city` (город), `temperature_c` (текущую
   температуру в °C), `country` (страну).
4. Температура берётся из `current_condition[0].temp_C`, страна — из
   `nearest_area[0].country[0].value`. Название города сохраняется из входного
   файла. Прогноз и ощущаемая температура для расчётов не используются.
5. `group_by_country()` вычисляет число городов, среднее арифметическое,
   минимум и максимум. Страны выводятся в алфавитном порядке; среднее округляется
   до двух знаков только при выводе.

Страны и температуры не заданы в коде: они получаются через API, а все
статистические значения рассчитываются по полученным данным.

## Пример фактического запуска

При проверке 9 октября 2026 года все восемь запросов завершились успешно:

```text
Погода по городам:
Moscow, Russia +15 °C
Khabarovsk, Russia +8 °C
Saint-Petersburg, Russia +11 °C
Vienna, Austria +14 °C
Izhevsk, Russia +11 °C
Perm, Russia +9 °C
NhaTrang, Vietnam +28 °C
Villach, Austria +11 °C

Статистика по странам:
Austria - 2 cities, avg: +12.5 °C, min: +11 °C, max: +14 °C
Russia - 5 cities, avg: +10.8 °C, min: +8 °C, max: +15 °C

```

Это пример результата проверки, а не фиксированные данные приложения.
При следующих запусках погода может измениться.

## Обработка ошибок

Прогресс и ошибки выводятся в `stderr`, отчёт — в `stdout`.
Тайм-аут одного запроса по умолчанию — 20 секунд. При сетевых сбоях и HTTP
408/429/5xx выполняются максимум два дополнительных запроса с паузами
1 и 2 секунды. Некорректный JSON, отсутствие обязательных полей и постоянные
HTTP-ошибки выводятся как ошибки соответствующего города.

Если отдельный город недоступен, обработка остальных продолжается.
Статистика включает только успешно полученные данные; программа явно сообщает
о неполноте результата и возвращает код **1**. При успехе код **0**, при
некорректных аргументах — **2**, при прерывании пользователем — **130**.
Отсутствующий или пустой файл обрабатывается до HTTP-запросов.

## Проверки

```bash
python -m unittest discover -v
```

Тесты используют стандартные `unittest` и `unittest.mock` и работают без сети.
Проверяются исходные списки, повторы между файлами, UTF-8 BOM, разбор API,
вычисления, формат вывода, тайм-ауты, повторные запросы и частичные ошибки.
GitHub Actions запускает их на Windows и Linux с Python 3.10, 3.12 и 3.13.
